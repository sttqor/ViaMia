# предложение: заказ туров и уведомления

статус: **обсуждение**, ничего не реализовано. 21.11.2026.
пометки: **[15.12]** — успеваем к выпуску, **[после]** — после выпуска.
пути файлов — по основной папке (main + незакоммиченное разбиение `App.jsx` на `src/views/*`).

## что есть сейчас (по коду)
- заказ — `src/views/Booking.jsx`: один тур, дата из `upcomingDates()`, 1–10 гостей, имя + контакт → `confirmBooking()` в `src/App.jsx` → `submitBookingRequest()` (`src/api.js`) пишет строку в `booking_requests`. сумму и агентство ставит триггер `booking_fill` (`supabase/schema.sql`).
- после заявки турист сразу попадает в билет — `src/views/TicketView.jsx`, статусы pending / confirmed / declined / cancelled / done. список броней — в профиле (`src/views/ProfileView.jsx`).
- статус обновляется только при синхронизации аккаунта (`fetchMyBookings()` в `src/useAccountSync.js`), то есть когда турист вошёл и открыл приложение. **гость без аккаунта статус не узнает никогда**: читать `booking_requests` ему нельзя (правило `booking_read_own` только для authenticated).
- агентство: вкладка заявок `BookingsTab` в `src/agency/AgencyApp.jsx`, `setBookingStatus()` в `src/agency/agency-api.js`. права на правку — только колонка `status` (`grant update (status)`).
- «маршрут» (`src/views/RouteView.jsx`) — один день без дат, список туров по порядку + навигатор (`src/Navigator.jsx`). к броням не привязан.
- у тура нет поминутной программы: есть `meeting`, `lat/lng`, `highlights[]`, `includes[]`, `images[]`. гидов в базе нет.
- push, email-рассылок, realtime-подписок в коде нет.

## как у похожих сервисов (поиск 21.11.2026)
| что | Viator | GetYourGuide | Airbnb Experiences | Tripster / Sputnik8 | Klook |
|---|---|---|---|---|---|
| подтверждение | мгновенное или «по запросу»: заявка pending, оператор подтверждает в кабинете (48 ч по справке поставщика, 72 ч таймаут), **деньги списываются только после подтверждения** | в основном мгновенное | мгновенное | гид подтверждает кнопкой, сначала можно переписка | мгновенное, ваучер |
| несколько туров | — | корзина, одна оплата | по одной | по одной | корзина |
| после брони | письмо с билетом | в приложении: билет, контакты поставщика, как добраться, **работает офлайн** | общий чат брони со всеми гостями | чат с гидом в приложении; **контакты открываются после предоплаты** | ваучер, контакты оператора внизу |
| связь с гидом | через поддержку | через поддержку, жалобы «нет прямой связи с поставщиком» | чат, **запланированные сообщения** (при подтверждении, за 24 ч, за 2 ч) | чат по заказу | оператор пишет в WhatsApp за день |
| аккаунт | — | — | обязателен | кабинет создаётся сам по почте из формы | обязателен |

выводы для нас:
- **схема «заявка → подтверждение → потом оплата» — стандартная** (Viator «по запросу»). значит наш путь верный, а для оплаты позже: платит только после подтверждения.
- **таймаут ожидания нужен всем** — у Viator 48–72 ч. у нас туры короткие и бронируются «на завтра», поэтому 24 ч / за 12 ч до тура — разумно.
- **гид/агентство и турист должны иметь связь.** у GYG её нет — на это жалуются. в Средней Азии всё равно пишут в WhatsApp/Telegram (как у Klook). дешёвое решение к 15.12: после подтверждения — кнопки «WhatsApp / Telegram / позвонить» агентству (и гиду, если разрешено). свой чат — после.
- **контакты — только после подтверждения/оплаты** (Tripster) — совпадает с нашим вопросом 7.
- **запланированные сообщения** (Airbnb): агентство один раз пишет шаблон «за день до тура: …», приложение само шлёт. это и есть наши напоминания [после].
- **вход:** вместо отдельного экрана входа — как Sputnik8: почта в форме брони + код из письма прямо там → аккаунт создаётся сам. турист не замечает «регистрации».
- **корзина** есть только у крупных с оплатой (GYG, Klook) — подтверждает: корзину делаем вместе с оплатой.
- **офлайн-билет** (GYG) — у нас уже есть кэш, надо, чтобы «поездка» (гид, точка встречи, программа) тоже открывалась без сети.

источники: [Viator: после брони](https://help.supplier.viator.com/en/articles/151-what-happens-after-a-traveler-books-my-product), [Viator: глоссарий партнёра](https://partnerresources.viator.com/?p=5016), [GetYourGuide в App Store](https://apps.apple.com/us/app/id705079381), [Airbnb: запланированные сообщения](https://www.airbnb.com/help/article/3297), [Airbnb: как провести впечатление](https://www.airbnb.com/resources/hosting-experiences/a/how-to-host-a-smooth-experience-726), [Tripster FAQ](https://experience.tripster.ru/about/faq/), [Sputnik8: как забронировать](https://www.sputnik8.com/ru/pages/kak-zabronirovat-ekskursiiu), [Klook FAQ](https://www.klook.com/en-GB/faq), [Klook: обещания клиентам](https://www.klook.com/about/customer-promises/). часть фактов — из справки для поставщиков и обзоров, точные экраны приложений не проверял.

## путь туриста
1. **выбор.** карточка тура → «забронировать». **рекомендую: по одному туру, без корзины** [15.12]. корзина имеет смысл только с оплатой (одна оплата за всё) [после].
   - после отправки заявки вместо «готово» показывать «забронировать ещё на этот день» с 2–3 турами рядом — так несколько туров собираются без корзины.
2. **вход перед заявкой.** **рекомендую требовать вход (почта-код) для брони** [15.12]. без аккаунта нельзя ни прислать уведомление, ни показать статус на другом телефоне. затронет `Booking.jsx` (кнопка «войти и отправить»), `App.jsx` (`confirmBooking`), правило `booking_insert` (убрать anon).
3. **ожидание.** билет «ждёт подтверждения» + понятное «агентство ответит до N часов». при подтверждении — уведомление (см. ниже).
4. **подтверждено → «поездка».** билет превращается в экран поездки (см. «экраны»): гид, программа, точка встречи, «как добраться» → навигатор.
5. **в день тура.** напоминание за день и за 2 часа [после, нужен планировщик]; в приложении на главной — плашка «сегодня в 10:00 тур, встреча через 1 ч 20 мин» [15.12, считается на телефоне].
6. **после тура.** статус done → «оцените тур» [после].
7. **с оплатой (позже):** pending → confirmed → **awaiting_payment** → **paid** → done. турист платит только после подтверждения агентством — тогда не нужны возвраты за «агентство не смогло». корзина и одна оплата за несколько туров — здесь.

## путь агентства
1. новая заявка → уведомление (email сразу [15.12], push [после]) + счётчик «новые» в кабинете (фильтр `new` уже есть).
2. в карточке заявки: подтвердить / отклонить **с причиной** (сейчас без причины) / «предложить другую дату» [после].
3. при подтверждении — форма «детали для туриста»: выбрать гида из своего списка, время встречи, комментарий («возьмите воду»). программа берётся из самого тура.
4. в кабинете — раздел «гиды»: имя, фото, языки, телефон (виден туристу только после подтверждения).
5. в редакторе тура (`src/agency/TourEditor.jsx`) — блок «программа»: пункты время + место (+ точка на карте через `PickMap`).
6. после тура — «проведён» (уже есть `ag.bk.markDone`).

## экраны
**вариант А — «поездка» вместо билета (рекомендую) [15.12]**
расширяем `TicketView.jsx`, без новой вкладки. блоки сверху вниз:
1. обложка + статус (как сейчас) + дата и время встречи крупно;
2. **гид**: фото, имя, языки, «позвонить / написать» — только когда confirmed;
3. **точка встречи**: мини-карта (`MiniMap`), адрес, «как добраться» → навигатор (`Navigator.jsx`, тот же путь, что `onNavigate` в `RouteView`);
4. **программа**: таймлайн пунктов (время, место), на карте — линия;
5. **от агентства**: последнее сообщение/изменение + история;
6. код брони, «отменить» (как сейчас).

в профиле список броней → **«мои поездки»**, по датам: «сегодня / скоро / прошедшие».

**вариант Б — брони внутри вкладки «маршрут» [после]**
у «маршрута» появляются дни; подтверждённые туры встают в свой день закреплёнными, свои места туриста — между ними. красиво, но `RouteView.jsx` без дат, а маршрут хранится просто списком id (`osh-guide-v1`, `profiles`) — это переделка модели, после выпуска.

## уведомления
| событие | кому | канал | когда |
|---|---|---|---|
| новая заявка | агентство | email (Resend) + плашка в кабинете | [15.12] |
| заявка без ответа 12 ч | агентство (повтор), админ | email | [после] (pg_cron) |

| напоминание за день / за 2 ч | турист | push (запасной — email) | [после] |
| «оцените тур» | турист | push / в приложении | [после] |

как устроено:
- **в приложении [15.12]:** колокольчик со списком `booking_events`, подписка Supabase Realtime на свои события, при открытии — подтянуть непрочитанные. затронет `useAccountSync.js`, шапку в `HomeBlocks.jsx`, `ProfileView.jsx`.
- **email [15.12]:** Database Webhook (или триггер + `pg_net`) → Edge Function → Resend. Resend всё равно нужен для входа по почте (сейчас коды не доходят до настоящих пользователей) — один сервис на обе задачи. шаблоны ru/en.
- **push [после]:** `@capacitor/push-notifications` + Firebase (FCM для android, для ios через APNs-ключ). нужны аккаунт apple developer, проект firebase, `push_tokens`, edge function — риск сорвать 15.12. в вебе на iphone push работает только с сайтом на экране «Домой» — не рассчитывать.
- переключатель «уведомления о турах» (`notifs` в `SettingsProvider`) сейчас ничего не делает — привязать к email/push или убрать.

## риски
- **оплата и комиссия:** без юрлица брать деньги нельзя → «оплата на месте», честно в карточке и билете (шаги брони в `Detail.jsx` уже есть). комиссия с агентства — договором, не в приложении.
- **app store:** туры — услуги в реальном мире, правило 3.1.3(e): apple-оплата не нужна, своя оплата разрешена.
- **отмена/возврат:** правило «бесплатная отмена за N часов» показывать в билете (у тура сейчас флаг `freeCancel`). с оплатой — кто и когда возвращает деньги.
- **агентство не ответило:** статус `expired` через 24 ч (или за 12 ч до тура) + письмо туристу с похожими турами + сигнал админу. без планировщика — проверка при открытии приложения/кабинета [15.12], настоящий таймер [после].
- **приватность:** фото и телефон гида — только туристу с подтверждённой бронью; контакт туриста — только его агентству (уже так). в `src/privacy-text.js` и анкетах магазинов добавить: имя/фото гида, email-уведомления, push-токены.
- **двойные брони** — лимита мест нет, агентство отклоняет само. «мест на дату» [после].
- **время:** `meet_at` в timestamptz, показывать в поясе Оша (Asia/Bishkek), а не телефона.

## вопросы ко мне
1. **бронь только после входа по почте?** совет: да — иначе нельзя ни уведомить, ни показать статус.
2. **корзина сейчас или по одному туру?** совет: по одному + «забронировать ещё», корзина — вместе с оплатой.
3. **экран после подтверждения:** «поездка» в билете (А) или туры во вкладке «маршрут» по дням (Б)? совет: А к 15.12, Б после.

7. **показывать туристу телефон гида или только «написать агентству»?** совет: телефон — только после подтверждения и если агентство отметило «можно».
