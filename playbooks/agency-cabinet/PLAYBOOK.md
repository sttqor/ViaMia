# плейбук: кабинет агентств и понятные туры

## цель
турагентства оша сами выкладывают туры через `/agency`, но к туристам попадают
**только проверенные организации и только проверенные туры**. турист во вкладке
«туры» сразу понимает, что к чему: кто организатор, проверен ли он, что будет,
сколько стоит и длится, что включено, куда прийти и как проходит бронь.

## что решил пользователь (20.11.2026)
1. приложение уже работает на vercel, supabase-проект «ViaMia» живой.
2. сейчас делаем: кабинет агентств + туры, понятные туристу.
3. модерация обязательна; пускаем не любого — только аккредитованную организацию.
4. telegram-бота нет — уведомления агентствам **отложены**, обсудим потом.
5. вход только по почте (sms не подключены).
6. как хранить фото — на моё усмотрение (решение ниже).
7. пользователей пока нет, кроме самого владельца.
8. новые строки — пока только ru и en, остальные 10 языков потом.

## мои решения (можно поменять)
- одно агентство на аккаунт; регистрация сама, но статус «на проверке», пока админ не одобрит.
- статусы агентства: на проверке → одобрено / отклонено (с причиной) / заблокировано.
- статусы тура: черновик → на проверке → опубликован / отклонён (с причиной); агентство может скрыть.
- правка опубликованного тура или юр. данных агентства → снова на проверку.
- фото — supabase storage, бакет `tour-photos` (публичный), перед загрузкой сжатие до 1600 px webp.
  документы — приватный бакет `agency-docs`, видят только владелец и админ.
- модерация — отдельная страница `/admin`, доступ по таблице `admins`.
- оплаты нет: бронь = заявка, агентство подтверждает или отклоняет, оплата на месте.

## правила
- **схема модерации** — `toolbox/01-agency.sql`. запускать после `supabase/schema.sql`. все права проверяет база
  (rls + триггеры `agency_guard` / `tour_guard`), экран только показывает. менять права — только здесь.
- **после любой правки sql** — прогнать `toolbox/02-test-agency.sql` вместе с ним в транзакции с откатом
  и сверить итоги с ожидаемыми в шапке файла. живую базу тестом не менять.
- **линтер supabase** (Advisors → Security) после правок схемы: предупреждение про `is_admin` и `cancel_booking` ожидаемо (см. комментарий в `01`), остальное разбирать.
- **админ** — добавлять только через `toolbox/03-make-admin.sql`, ключ service_role в код не класть.
- **одобрение агентства** — по шаблону `toolbox/accreditation-checklist.md`; отказ всегда с причиной.
- **тур на проверку** — только если выполнен `toolbox/tour-checklist.md`; он же — функция `checklist()`
  в `src/agency/TourEditor.jsx`, правится в двух местах сразу.
- строки кабинета — `src/locales/agency.js` (ru/en), подключены в `DICT` в `src/i18n.js`. новый ключ `ag.*`/`adm.*` — только туда.
- маршрут `/agency` и `/admin` — `src/Root.jsx`; на vercel все пути отдаёт `index.html` (`vercel.json`).
- проверка, что у всех ключей есть текст, — `node playbooks/agency-cabinet/toolbox/check-keys.mjs .` (запускать из корня проекта).
- код лежит в `src/agency/`: `AgencyApp.jsx` (кабинет), `TourEditor.jsx`, `AdminApp.jsx`, `ui.jsx`,
  `agency-api.js`, `compressImage.js`, `agency.css`; карта выбора точки — `PickMap` в `src/OshMap.jsx`.
- применять sql к живой базе, коммитить, пушить — **только после «да» пользователя**.
- перед правками `npm run lint`, после — `npm run build`.
- строки интерфейса только через `t()`; новые ключи — в ru и en (остальные языки возьмут en/ru сами).
- цвета только токенами, без `#fff`/`rgba` для фонов; кнопки 48/14, чипы 36/999, карточки 20.
- не придумывать реальные цены и контакты агентств — заглушки.
- уведомления в telegram не делать, пока пользователь не вернётся к этому.
- новый файл, скрипт, шаблон или документ для этой задачи — класть в `toolbox/` и добавлять сюда правило со ссылкой.

## готово, когда
- агентство входит по почте на `/agency`, заполняет организацию, грузит документы, видит «на проверке».
- пока агентство не одобрено, его туры не видны туристам и забронировать их нельзя (даже через api).
- агентство не может само себя одобрить или опубликовать тур (проверено тестом `02`).
- админ на `/admin` видит заявки агентств и туры, открывает документы, одобряет / отклоняет с причиной.
- одобренный тур появляется во вкладке «туры» (режим «с гидом») с названием агентства и меткой «проверено».
- в карточке тура понятно: организатор, длительность, языки, цена, что включено, точка встречи на карте,
  и три шага брони (заявка → подтверждение агентства → оплата на месте).
- агентство видит заявку, подтверждает — турист видит «подтверждено» в билете.
- `npm run lint` и `npm run build` без ошибок; ничего не закоммичено без просьбы.
